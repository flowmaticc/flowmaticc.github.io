2. What the app does with your traffic

Garbillo uses Android's VPN feature to create a local VPN that doesn't connect to any external server. Only DNS queries go through it (the domain names apps want to reach, e.g. ads.example.com).

  • If the domain is on a block list (ads, tracking or threats such as phishing and malware), the app answers with an empty address (0.0.0.0) and the connection never happens.
  • If not, the query is forwarded to your usual DNS server (your carrier's or the one you've set), exactly as without the app. Only if the network announces no DNS server is Quad9 (9.9.9.9) used, a non-profit service that doesn't store your IP.
  • If you turn on encrypted DNS (Settings → Encrypted DNS), allowed queries go encrypted over TLS to the service you choose (Quad9, Cloudflare or Mullvad) instead of your usual DNS. Nobody on your network, including your carrier, sees which domains you look up; the chosen service does receive them, as your usual DNS would. On a Wi-Fi with a login page, the network's DNS is used until you sign in.
  • All other traffic (websites, messages, videos…) doesn't go through the app. The app can't see the content of what you do.

4. The app's internet connections

  • GitHub (raw.githubusercontent.com, api.github.com, github.com): downloading block lists and checking for new app versions.
  • Quad9, Cloudflare or Mullvad: only the one you choose, and only if you turn on encrypted DNS (see section 2). Quad9 is also used, unencrypted, if the network announces no DNS.
  • adaway.org: only if you turn on the optional AdAway layer.
  • The website you choose, only when you use “View on the web” in the history. It loads in a separate window, without your browser's cookies, and its data is deleted when you close it.
  • Flowmaticc's report service, only when you tap “Report for review” (in the app) or send the form on the website. See below.
  • The same service, for error reports, only if you turn them on (the app asks you). See “Error reports”.

With “Download only on Wi-Fi” (on by default), automatic downloads and error reports only happen on Wi-Fi or another network without a data cap.

Site reports

If you choose to report a domain, only this is sent: the domain, the reason you pick, the note you write (if any), whether it comes from the app or the website, and the app version. Your history, apps and any identifiers are never sent.

The service runs on Cloudflare Workers and stores the report as an issue in a private Flowmaticc GitHub repository, where we review it to improve the lists. We don't store your IP address. To prevent abuse, the number of reports per connection and day is limited using a hash of the IP and the day that cannot be reversed (for IPv6, of your network block, not the exact address) and is deleted after two days. Cloudflare processes the connection like any web server (see its privacy policy).

Please don't put personal data in the note. Reports are kept while useful for analysis; write to us if you want one deleted.

Error reports (optional)

The app asks whether you want to send them; nothing is sent by default. If you turn them on, when something fails (the app closes, a list doesn't download, an update doesn't install…) it's noted on the phone and sent at most once a day:

  • the kind of failure (from a fixed list) and, where relevant, a short code such as “HTTP 404”;
  • the place in Garbillo's code where it happened and the technical error type (e.g. java.io.IOException), without the message text;
  • how many times it happened and between which days (no times);
  • Garbillo's version and channel, the Android version, the phone brand, the blocking level, how many extra lists you use and whether threat protection is on.

Websites or domains, history, your apps, your network, location and any phone identifier are never sent, and there's no way to link two reports from the same phone. Before it leaves you can see the exact report in Ajustes → Informes de errores → Ver qué se enviaría (Settings → Error reports → See what would be sent), delete it or turn reports off. They're stored in the same private repository as site reports, grouped by kind of failure, with the same guarantees: your IP is not stored.

No personal data is sent in these downloads, but, as with any internet connection, those servers can see your IP address. See GitHub's privacy statement.

5. Permissions

The complete list of permissions and what each is used for is on the Garbillo page. The app does not ask for location, camera, microphone, contacts, SMS, files, accessibility or screen capture.

6. Third parties

No data is shared with third parties, except as described for reports (Cloudflare and GitHub as service providers) and the encrypted DNS service you choose (Quad9, Cloudflare or Mullvad), which receives allowed queries: see their policies at quad9.net, cloudflare.com and mullvad.net. The block lists are the work of their authors (Hagezi, GoodbyeAds, 1Hosts, AdAway, StevenBlack) and are downloaded directly from their public repositories.

7. Your rights

Since we don't collect personal data, we hold no data about you to access, correct or delete. Local data (history and settings) is under your control: you can delete it from the app or by uninstalling it. For any question, write to gestiona.optimiza@gmail.com. You can also contact the Spanish Data Protection Agency (AEPD).

8. License and warranty

Garbillo is free software under the GNU GPL v3. It is provided without any warranty: blocking domains may stop some site or app from working properly. If so, you can allow the domain from the history or turn the filter off.

9. Changes to this policy

If the way the app handles data changes, we'll update this page and the date above. Code changes can be reviewed publicly on GitHub.
